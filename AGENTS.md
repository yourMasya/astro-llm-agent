# astro-llm-agent

Тестовое задание Senior LLM Engineer: LLM-агент, который по текстовому запросу
исследователя анализирует астрономические временные ряды (кривые блеска),
вызывает Python-инструменты и формирует проверяемый отчёт о периодичности
и аномалиях.

## Цель и признак завершения

- Цель: воспроизводимый репозиторий с агентом, baseline, 20 задачами,
  метриками, стресс-тестами (≥5 отказов) и техотчётом до 2 страниц.
- Завершение: `scripts/run_all.sh` проходит целиком — генерация данных,
  eval агента и baseline, стресс-тесты, формирование таблиц метрик и отчёта.

## Правила проекта

- Разработчик-ориентированные тексты (README, отчёты, комментарии
  в регрессионных файлах) — по-русски. Комментарии в коде — по-английски.
- Все числа в ответе агента берутся только из результатов инструментов.
  Агент не исполняет произвольный код и не пишет в файлы данных.
- Детерминизм: генератор данных и baseline — фиксированные seed;
  LLM-агент — температура 0.
- Данные и ground truth коммитятся в репозиторий; прогон eval не требует
  сети, кроме самого вызова LLM.
- Секреты (токены) в репозиторий не попадают: ключ читается из env.

## Решения, принятые и не пересматриваемые

- Набор данных — синтетический бенчмарк, калиброванный на свойства наземных
  обзоров (неравномерная дискретизация, сезонные пропуски, шум): только так
  на 20 задачах есть проверяемая ground truth по аномалиям. Путь для реальных
  открытых CSV (OGLE/ASAS-SN) предусмотрен в `loader.py`.
- LLM-планировщик — DeepSeek-V4-Flash через корпоративный LiteLLM-прокси
  (OpenAI-совместимый), ключ из `INFERENCE_API_KEY`.
- Финальный ответ агента — строгий JSON (периодичность, период, единицы,
  выбросы/вспышки/провалы, примечания): по нему считаются количественные
  метрики.
- Метрика применяется только к теме, которую спрашивает запрос:
  `expected.periodic` есть в задачах про периодичность, `flares/dips` — про
  вспышки/провалы, `outliers_indices` — про выбросы. Задача, где агент
  «правильно не тронул» неспрошенную тему, не штрафуется.
- Guardrails цикла: лимиты шагов (24), вызовов (20), невалидных JSON (3),
  минимум вызовов до финала (2), таймаут (240 с) и «стабильно недоступный
  инструмент» (`max_consecutive_errors: 3` — при трёх сбоях подряд одного
  инструмента агент честно завершает задачу вместо прожигания бюджета шагов).

## Чего делать нельзя

- Не добавлять инструмент произвольного выполнения кода (code execution):
  это размывает границу «LLM планирует, инструмент считает».
- Не менять ground truth после генерации, чтобы «подогнать» метрики.
- Не хранить API-ключи в файлах проекта.
