# Протокол измерения v2 (pre-registration)

Зафиксирован ДО генерации данных и прогонов. Любое изменение правил ниже —
новая версия протокола и новый прогон; результаты v2 при этом не
пересматриваются, а помечаются версией.

## 1. Проблема, которую закрывает протокол

Отчёт v1 заявлял F1 по выбросам = 1.0. Диагностика
(`scripts/analyze_benchmark_sensitivity.py`) показала: причина — не утечка
ground truth в модель (агент и baseline видят только кривую и запрос;
`ground_truth.json` не передаётся в промпт, инструменты и executor — проверено
по коду), а **вырожденность бенчмарка на оси аномалий** (design leakage):
амплитуды инъекций выбраны в абсолютных единицах (выбросы 4.0–8.0, вспышки
0.15–0.50, провалы 0.08–0.25) при шуме 0.008–0.025, т.е. 160–1000σ против
порога 5σ; плюс задачи отбирались по детектируемости.

v2 делает ось аномалий различающей: амплитуды инъекций — в единицах шума
ряда, реалистичные для наземной фотометрии. Пороги детекторов и метрики **не
меняются** — иначе сравнение v1↔v2 нельзя атрибутировать.

## 2. Что меняется (зафиксировано до прогона)

Новый набор `data_hard/`: 20 кривых `h000`–`h019` (соответствуют задачам
t01–t20), те же типы сигналов, что в v1-задачах (типы берутся из
`data/ground_truth.json` для исходных кривых bXXX), те же параметры обзора
(каденс, сезонность, пропуски, шум) из `config.yaml`, новый детерминированный
сид через id кривых.

Амплитуды аномалий — множители к шуму ряда `sigma_base` (распределения
зафиксированы, не подбираются после прогона):

| Аномалия | v1 (абс.) | v2 (в σ шума) | Обоснование |
|---|---|---|---|
| Выбросы | 4.0–8.0 | `U(3,8)·σ` | часть — ниже гарантированного порога 5 MAD / 3·err |
| Вспышки | 0.15–0.50 | `U(4,10)·σ` | пересекает порог 5σ: часть не детектируется |
| Провалы первичные | 0.08–0.25 | `U(3,8)·σ` | пересекает порог 4σ |
| Провалы вторичные | 0.010–0.020 | `U(1.2,2.5)·σ` | остаются мельче первичных (нет ложной P/2) |

Ground truth (периоды, индексы выбросов, интервалы вспышек/провалов)
пересчитывается из генератора для новых кривых — это истина «по построению»,
уже определённая до прогона, а не подгонка под результат.

## 3. Что НЕ меняется

- Пороги детекторов: выбросы 5 MAD + |Δ|>3·err, вспышки 5σ / min_points 3,
  провалы 4σ / min_points 3 (config.yaml).
- Метрики: F1 по индексам выбросов (допуск ±2), hit-rate вспышек/провалов,
  период ±5%, единицы, caveats, стоимость.
- Структура `expected` задач (те же ключи, те же правила «метрика только к
  запрошенной теме»).
- LLM-планировщик, инструменты, baseline-конвейер.

## 4. Правила против порочного круга

1. **До прогона** фиксируются: распределения амплитуд (§2), сид, пороги
   детекторов, метрики. После просмотра результатов эти параметры не
   меняются.
2. **Планка различающей силы**: считается «потолок достижимого» — результат
   детекторов против ground truth на `data_hard`. Если потолок по выбросам
   ≥0.95 — набор объявляется вырожденным, это фиксируется в отчёте как
   результат (не «чинится»); следующий шаг — протокол v3 с уменьшенными
   амплитудами или смена оси сложности.
3. Агент интерпретируется **относительно потолка**, а не абсолютно: если
   агент не превосходит потолок — он работает на пределе инструментального
   слоя; если заметно ниже — это измеряемое качество планирования.
4. Все числа в отчёте генерируются скриптами из логов (`run_eval.py`,
   `check_hard_ceiling.py`). Ручные правки цифр запрещены.
5. Запрет на редактирование ground truth после генерации (тот же, что в
   AGENTS.md проекта).
6. Ограничение фиксируется явно: бенчмарк — самооценка без внешнего
   рецензента; защита от подгонки — воспроизводимость (данные, код, логи в
   репозитории) и pre-registration, а не «объективность» автора.

## 5. Команды

```bash
.venv/bin/python scripts/generate_hard_dataset.py   # data_hard/ + tasks/tasks_hard_20.json
.venv/bin/python scripts/check_hard_ceiling.py      # потолок достижимого
.venv/bin/python eval/run_eval.py --only baseline \
  --data-csv data_hard/dataset.csv --data-truth data_hard/ground_truth.json \
  --tasks-file tasks/tasks_hard_20.json --log-root logs_hard \
  --results-json report/metrics_hard.json --results-md report/metrics_table_hard.md
.venv/bin/python eval/run_eval.py --only agent --only both ...  # см. README
```
