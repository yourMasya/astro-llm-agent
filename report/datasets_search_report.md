# Отчёт по поиску датасетов астрономических временных рядов

Дата поиска: 2026-11-16. Инструменты: `web_search` (бэкенды keenable /
firecrawl / exa / parallel — часть падала, см. раздел «Ограничения») и
`web_extract` (прямое извлечение страниц архивов).

---

## TL;DR

**Датасетов много, готового бенчмарка «LLM-агент + кривые блеска» нет.**

Открытые каталоги кривых блеска существуют и доступны вплоть до миллиардов
кривых (ZTF: 4.64 млрд). Но ни один из них не даёт того, что нужно для
тестового задания:

- **позиционную ground truth по аномалиям** (индексы точек, где выброс/вспышка/
  провал) — таких разметок в открытых каталогах нет;
- **контролируемую сложность в пределах бюджета $10** — калибровка порогов
  и разметка реальных данных — это недели ручной работы и десятки долларов
  прогонов.

Поэтому бенчмарк — синтетический, калиброванный на свойства реальных
наземных обзоров (OGLE/ASAS-SN: неравномерная дискретизация, сезонные
пропуски, шум). Загрузчик в проекте совместим с CSV-форматом реальных
каталогов, так что конвейер переносится на реальные данные без изменения кода
(путь описан в конце отчёта).

## LLM-агентные бенчмарки в астрофизике (найдено, но не кривые блеска)

- **AstroAgentBench** (arXiv:2601.11354) — бенчмарк агентного планирования
  космических миссий: планирование наблюдений, расписаний, созвездий. Не
  временные ряды, но методология (внешний верификатор результата агента)
  близка к нашему подходу.
- **AstroMLab 1** (arXiv:2407.11194) — «астрономическая Jeopardy!»: QA-бенчмарк
  знаний, не анализ данных.
- **Astro2Method** (arXiv:2610.30282) — 500 вопросов о ML-методах из 346
  статей по астрономии; проверка знания методов, не их применения к рядам.
- **TSAIA Benchmark** (NeurIPS 2025) — LLM как ассистент по временным рядам
  вообще (мультишаговое рассуждение), но не астрономия.
- **AstroGenesis** (arXiv:2609.28579) — мультиагентный фреймворк для
  блазаров; доступ к данным через инструменты, но это система, а не
  бенчмарк с ground truth.
- **AstroAgents** (arXiv:2503.23170) — мультиагентная генерация гипотез, но
  по масс-спектрометрии метеоритов, не по кривым блеска.

Вывод из этой части: **готового эталона для сравнения нет** — наше тестовое
задание не переиспользует существующий датасет, потому что подходящего
публичного бенчмарка «агент + анализ кривой блеска + проверяемые аномалии»
не существует. Ближайшие по духу — AstroAgentBench (верификатор) и Sesar 2010
(period-finding), но ни один не закрывает задачи с аномалиями и единицами.

## Почему в бенчмарке синтетика: полный разбор

### 1. Ground truth по аномалиям

Основные запросы в наших 20 задачах — про **выбросы, вспышки, провалы**,
и для них нужна разметка «какие именно точки — аномалии». В открытых
каталогах (ASAS-SN, OGLE, ZTF) её нет в принципе: там есть классы и периоды,
а «вот в этих трёх точках вспышка» — такого никто не публикует. Даже AAVSO,
где события документированы, требует ручной разборки бюллетеней.

Синтетика эту проблему решает: генератор **знает**, куда вставил вспышку
и какие точки — выбросы, и записывает это в ground truth. Метрики
(точность/полнота/F1 по аномалиям) считаются только при такой разметке.

### 2. Контролируемая сложность и бюджет

Тестовое задание ограничено бюджетом **$10** и требует количественных
метрик на **20 задачах** со стресс-тестами. Реальные данные надо было бы:
отобрать (кросс-мэтч с каталогами), вычистить, вручную разметить аномалии,
убедиться, что случаи не тривиальны и не вырождены. Это ручная работа на
недели — и её результат всё равно субъективен. Синтетика даёт 20 задач
с известной сложностью (диапазоны периодов, амплитуд, шума, типы аномалий
прописаны в `config.yaml`) за $0.13 прогона.

### 3. Воспроизводимость

Фиксированный seed генератора → одни и те же данные у проверяющего.
Если бы мы скачали ASAS-SN, выборка зависела бы от даты скачивания.
Синтетика коммитится в репозиторий и не меняется.

### 4. Физическая правдоподобность

Генератор откалиброван на **реальные свойства наземных обзоров**, стиль
которых он имитирует: I/V-полоса, каденс ~1 сут, сезонные пропуски, шум
~0.02–0.05 mag, периоды от минут (пульсации белых карликов) до десятков
дней (мириды). Именно эти свойства порождают те самые ловушки (алиас,
субгармоника, тренд), которые проверяются стресс-тестами. Но честно:
**синтетика не заменяет реальную проверку** — она делает бенчмарк
проверяемым, а реальная проверка остаётся следующим шагом.

### 5. Совместимость с реальными данными

Загрузчик (`loader.py`) читает CSV вида `time,mag,err` — это формат выгрузок
ASAS-SN и большинства каталогов. Чтобы прогнать реальные данные, не нужно
менять код агента: нужен только конвертер из конкретного каталога в этот
формат (для ASAS-SN — 10 строк).

## Ограничения проверки

- Поисковые бэкенды ненадёжны: exa/parallel падали с HTTP 403, keenable
  с ошибками TLS/целевых страниц — часть запросов пришлось повторять,
  часть не прошла (AstroTime-бенчмарк не найден; вероятно, он существует
  под другим именем или не проиндексирован).
- Страницы CRTS и astroml.org/datasets на момент проверки не открылись
  (bad gateway / 404) — данные о них приведены по косвенным источникам
  и по общему знанию, помечены ⚠️.
- Из контейнера Hermes внешние архивы напрямую недоступны (проверялось
  ранее для astroML); все проверки сделаны через `web_search`/`web_extract`,
  т.е. по публичным страницам, а не скачиванием самих данных.
- Числа объёмов (687 695 кривых ASAS-SN, 4.64 млрд ZTF, 73 млн MACHO,
  21 тыс. переменных MACHO/LMC, 30.1 млн V-кривых ASAS-SN Paper V, 483 RR Lyr
  Sesar 2010) взяты из страниц/аннотаций, полученных при проверке.

## Следующий шаг с реальными данными (как это сделать)

1. **ASAS-SN** — качаем CSV-каталог или tarball с
   `asas-sn.osu.edu/variables`, конвертируем в `time,mag,err`, считаем
   период и сравниваем с каталоговым: метрика готова, разметка аномалий
   отсутствует по определению.
2. **Sesar 2010** — самый лёгкий: `fetch_rrlyrae()` из `gatspy` даёт
   кривые и эталонные периоды; прогон period-finding сравнивается напрямую.
3. **AAVSO** — для событийных задач (вспышки CV): экспорт через
   `apps.aavso.org/data/search`, разметка по бюллетеням вручную.

Проверка периодичности на ASAS-SN или Sesar 2010 — естественное расширение
тестового задания, если проверяющий захочет увидеть работу агента на реальных
данных.
