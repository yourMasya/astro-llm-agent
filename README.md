# astro-llm-agent — LLM-агент для анализа кривых блеска

Тестовое задание **Senior LLM Engineer**: агент по текстовому запросу
исследователя анализирует астрономические временные ряды (кривые блеска),
сам планирует вычисления, вызывает Python-инструменты и выдаёт проверяемый
отчёт о периодичности и аномалиях. Числа считают инструменты — LLM только
планирует; это главная граница автономности.

В репозитории: 20 задач с ожидаемыми результатами, детерминированный
baseline, таблица метрик (точность/стоимость/надёжность), 9 стресс-тестов
отказов и их исправлений, логи вызовов инструментов, техотчёт ≤ 2 страниц.

## Быстрый старт

```bash
# окружение (Python 3.12)
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

# данные уже сгенерированы и закоммичены (data/*); при желании — перегенерация
.venv/bin/python scripts/generate_dataset.py

# юнит-тесты
.venv/bin/python -m pytest tests/ -q

# eval: baseline (без LLM, ~1 мин) и агент (нужен INFERENCE_API_KEY)
.venv/bin/python eval/run_eval.py --only baseline
.venv/bin/python eval/run_eval.py --only agent

# стресс-тесты (агентные сценарии требуют LLM; --quick пропускает S6)
.venv/bin/python stress/stress_tests.py

# всё сразу
bash scripts/run_all.sh
```

Результаты: `report/metrics_table.md`, `report/metrics.json`,
`logs/agent/<task>.jsonl`, `logs/baseline/<task>.jsonl`.

## Данные

Бенчмарк — синтетические кривые блеска, воспроизводящие свойства наземных
обзоров (OGLE/ASAS-SN): неравномерная дискретизация (джиттер каденса),
сезонные окна и пропуски, гетероскедастичный шум. Классы сигналов:
периодические (RR-лироподобные, гармоники), затменные двойные (провалы),
вспыхивающие, стационарные, с выбросами, с трендом. Ground truth известна
для каждой кривой (период, индексы выбросов, интервалы вспышек/провалов) —
только так на 20 задачах есть количественно проверяемые ожидаемые
результаты. У открытых данных нет попиксельной разметки аномалий, поэтому
они используются как контрольная выборка, а не как источник ground truth.

**Реальные открытые данные**: загрузчик `src/lightagent/data/loader.py`
принимает любой CSV в формате `id,time_days,flux,flux_err` (совместим с
экспортом OGLE/ASAS-SN после перевода магнитуд в относительный поток;
время — в сутках). Пример подключения:

```python
from lightagent.data.loader import load_dataset
ds = load_dataset("my_real_curves.csv")   # truth_path не обязателен
```

## Архитектура агента

Один цикл «планирование → выполнение»:

```
запрос исследователя
   │
   ▼
LLM-планировщик (DeepSeek-V4-Flash через LiteLLM-прокси)
   │   JSON: {"tool": "...", "args": {...}}  или  {"final": true, ...}
   ▼
ToolExecutor
   ├── валидация схемы (типы, диапазоны, enum, неизвестные аргументы)
   ├── семантические проверки инструмента (период в пределах наблюдаемых,
   │   дисперсия > 0, известный curve_id, единицы времени)
   ├── ретраи на транзиентные ошибки (2 повторные попытки, экспоненциальная пауза)
   └── сериализация результата (обрезка по лимиту контекста)
   │
   ▼
наблюдение возвращается планировщику ───► цикл до финального JSON
```

Инструменты: `list_curves`, `get_curve_info`, `periodogram`,
`check_alias`, `fit_linear_trend`, `detect_outliers`, `detect_flares`,
`detect_dips`, `plot_curve`. Исполнения произвольного кода агенту не даётся;
агент не пишет в данные и не видит ground truth.

Guardrails: максимум шагов (24) и вызовов (20) на задачу, лимит невалидных
JSON (3), требование минимум 2 вызовов инструментов до финала (задача не
решается «текстом»), таймаут 240 с, обрезка наблюдений, а также защита от
«стабильно недоступного инструмента»: при 3 сбоях подряд одного инструмента
агент честно завершает задачу вместо прожигания бюджета шагов.

Методы анализа: периодограмма Ломба–Скаргла с аналитической FAP (Baluev),
детренд линейного тренда ДО периодограммы (убирает ложный низкочастотный
пик трендов), проверка гармоник и субгармоники (ловушка затменных: два
провала за цикл дают P/2), проверка суточного алиасинга через спектральное
окно, MAD-выбросы с ограничением доли, вспышки/провалы по значимым
смежным сериям.

## Baseline

Детерминированный конвейер тех же численных методов: фиксированный порядок
вызовов, фиксированные пороги из `config.yaml`, всегда сутки. Он не понимает
естественный язык и единицы из запроса, поэтому на задачах «период в часах»
заведомо проигрывает агенту — это и есть измеряемая ценность планировщика.

## Метрики

- **Точность**: точность решения о периодичности; доля задач с верным
  периодом (отн. ошибка ≤ 5%); медианная отн. ошибка периода; F1 по
  выбросам (допуск ±2 индекса); hit-rate вспышек/провалов; обработка
  единиц времени (по логам вызовов); отражение обязательных оговорок.
- **Стоимость**: токены, оценка USD (тарифы deepseek-chat; точная цена
  прокси неизвестна), число вызовов инструментов, длительность.
- **Надёжность**: доля успешно завершённых задач; повторные попытки;
  ошибки валидации/семантики/инструментов; невалидный JSON планировщика.

Полная таблица — в `report/metrics_table.md`.

## Стресс-тесты (9 сценариев)

| # | Отказ | Исправление |
|---|---|---|
| S1 | Период в часах перепутан с сутками | конверсия по `time_unit` + согласованность с наблюдаемым диапазоном |
| S2 | 60-70% пропусков, модель «додумывает» | покрытие в `get_curve_info`, честная неопределённость (null + notes) |
| S3 | Затменная двойная: периодограмма даёт P/2 | проверка субгармоники f/2 → орбитальный период |
| S4 | Тренд создаёт ложный низкочастотный пик (FAP<1e-3) | линейный детренд перед периодограммой |
| S5 | Транзиентный сбой инструмента | 2 ретрая с экспоненциальной паузой, успех |
| S6 | Устойчивый сбой инструмента | guardrail-лимиты, честный отчёт об ошибке, без выдумки |
| S7 | Невалидные аргументы (тип/диапазон/имя/инструмент) | локальная валидация схемы до выполнения |
| S8 | Постоянная кривая (нулевая дисперсия) | отклонение периодограммы, «периодичность невозможна» |
| S9 | Неизвестный curve_id | семантическая ошибка со списком доступных id |

## Стоимость

Бюджет задания — до $10. Прогон 20 задач агентом стоит порядка
$0.1–0.3 (оценка по открытым тарифам deepseek-chat: $0.27/M входных,
$1.10/M выходных токенов; точная цена корпоративного прокси неизвестна).
Baseline стоит $0 (токенов не тратит).

## Ограничения и границы автономности

- Агент работает только с назначенным датасетом, только на чтение
  (кроме сохранения графиков в `report/plots/`).
- Нет инструмента исполнения кода: LLM не может «вычислить» число сам.
- Ground truth инструментам не передаётся; метрики считаются отдельно.
- Реальные открытые данные поддерживаются через тот же CSV-формат,
  но ground truth по аномалиям для них не определяется — поэтому количественная
  оценка ведётся на контролируемом бенчмарке.
